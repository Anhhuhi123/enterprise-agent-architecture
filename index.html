Tech stack

One Python codebase, two processes: API and worker

Modular monolith split by layer. Every AI call runs in the worker, never inside an HTTP request.

Runtime & web

  • Python 3.12
  • FastAPI + uvicorn
  • Pydantic v2, pydantic-settings

Data

  • PostgreSQL, JSONB for semi-structured data
  • SQLAlchemy 2 async + psycopg 3
  • Alembic migrations

Jobs & events

  • ARQ on Redis: 4 jobs at once, 20 min timeout, no auto-retry
  • redis-py pub/sub for SSE, rate limit

Agent / orchestration

  • langgraph state graph
  • langgraph-checkpoint-postgres chat memory
  • langchain-core chat model, tool, prompt interfaces only

Model access

  • httpx REST to OpenAI and Vidu, no SDK
  • Strict structured output from Pydantic schemas
  • Fake or real provider per type

Models (defaults)

  • LLM: OpenAI gpt-6-luna
  • Image: OpenAI gpt-image-2
  • Video: Vidu viduq3-turbo

Security

  • cryptography Fernet: provider keys, decrypted only in worker
  • pyjwt (HS256), argon2-cffi (Argon2id)

Media

  • FFmpeg / ffprobe: frames, joining clips
  • boto3 for S3 (signed URLs), Pillow

Build & quality

  • uv + uv.lock · Docker image python:3.12-slim with dev / prod targets · pytest + pytest-asyncio (fake providers only) · ruff
Layer rule: core, utils ← db, schemas ← ai, media ← services ← jobs/handlers, middlewares ← routes (checked by a test)
